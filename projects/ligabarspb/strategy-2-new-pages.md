## Шаблоны новых посадочных

### A. Шаблон ивент-посадочной "под повод" (корпоратив / ДР / девичник / мальчишник / свадьба)

Главная задача — **показать "это под мой повод"**, не "это коктейльный мастер-класс". Покупатель ещё не выбрал продукт.

#### Структура

1. **H1** — ровно по pillar-запросу
2. **Hero** — фото с реального ивента под этот повод (не сток!) + 3 буллета: число гостей / длительность / цены от
3. **"Подходит вам, если..."** — 4-5 пунктов, в которых заказчик узнаёт свою ситуацию
4. **"Какие форматы доступны под [повод]"** — 3-5 карточек:
   - Коктейльный мастер-класс — фото + цена от + ссылка на продуктовую
   - Винная дегустация — то же
   - Латте-арт — то же
   - Выездной бар (для крупных) — то же
   - Микс-формат — то же
5. **"Как это устроено"** — таймлайн в 4-6 шагов: заявка → согласование → программа → договор → ивент → отчёт
6. **Кейсы под этот повод** — 3-5 кейсов с числом гостей, отзывом, фото
7. **Цены и пакеты** — таблица: формат / число гостей / цена с человека / цена за группу
8. **Что входит в стоимость** — чёткий чеклист (продукты, оборудование, ведущий, аренда лофта или выезд)
9. **Часто задаваемые вопросы** — 8-12 вопросов, заточенных под этот повод
   - Для корпоратива: "договор", "счёт-фактура", "НДС", "выезд в офис"
   - Для девичника: "сценарий", "фото в подарок", "тематика"
   - Для мальчишника: "виски-дегустация", "стиль вечера"
   - Для свадьбы: "выездная регистрация", "welcome-зона", "фотозона"
10. **Форма заявки** — короткая, +поле "Повод" предзаполнено
11. **Sticky CTA**

#### Объём
2000–2500 слов. Это много, но по поводам Google и Яндекс любят глубокие лендинги.

#### Schema
- Service / Event
- BreadcrumbList
- FAQPage
- Offer (для каждого формата с ценой)
- AggregateRating (если есть отзывы под этот повод)

#### Под каждый повод — особое позиционирование

| Повод | Главное сообщение | УТП Лиги Универ |
|-------|-------------------|-----------------|
| Корпоратив | "Тимбилдинг, который реально сближает + люди уносят навык" | Школа барменов = настоящий формат, не "развлекалово". Юрлица, договор, выезд. |
| ДР взрослого | "Не банкет — формат, который запоминают" | Лофт в центре, фото на память, личный бармен |
| Девичник | "Уютный лофт, бьюти-формат, фотогенично" | Отдельная барная стойка для группы 6-12, инстаграм-зона |
| Мальчишник | "Виски, коктейли, бар-шоу — без пошлости" | Профессиональный формат, виски-дегустация, бар-шоу |
| Свадьба | "Welcome-бар + мастер-класс для гостей" | Выезд + лофт-вариант, чёткие тайминги |

### B. Шаблон сертификата (`/events/sertifikat/` и подстраницы)

Главная цель — **закрыть страх дарящего**: "вдруг ему не понравится / даты не подойдут / неудобно".

#### Структура hub-страницы `/events/sertifikat/`

1. **H1** — "Подарочный сертификат на мастер-класс в Лиге Универ — СПб"
2. **Hero** — крупно: цена от 4 290 ₽, "электронный за 1 минуту", "бумажный с упаковкой за 24 часа", срок действия 12 месяцев
3. **Карта получателей** — карточки-ссылки на подстраницы: Мужу / Жене / Парню / Девушке / Коллеге / Другу / Подруге / Маме / Паре
4. **Карта поводов** — карточки: ДР / Годовщина / 23 февраля / 8 марта / Новый год / Новоселье / Просто так
5. **Карта продуктов** — фото-карточки наших мастер-классов, кликабельны
6. **3 формата сертификата** — электронный / стандарт-крафт / премиум-коробка с разницей в цене 0 / 0 / +500
7. **Гарантия даты** — главное УТП vs агрегаторы: "Бронируем дату при покупке, не нужно потом договариваться"
8. **Возможность обмена** — внутри нашего меню, без доплат, на любой эквивалентный продукт
9. **Срок действия** — 18 месяцев (на 6 больше чем у агрегаторов — отстройка)
10. **Как купить** — 3 шага визуально
11. **Отзывы получателей подарков** — особый жанр: "ему/ей понравилось"
12. **FAQ** — 12-15 вопросов: "что если не успеют использовать", "можно ли обменять", "как продлить", "если человек не пьёт алкоголь", "можно ли вернуть"
13. **Корпоративная программа** — отдельный блок: "Подарки для команды от 10 человек, скидки от 15%"

#### Подстраницы по получателю

Каждая — около 1500 слов, с фокусом на конкретного получателя.

Пример `/events/sertifikat/muzhchine/`:
- H1: "Подарочный сертификат мужчине — впечатление в СПб от Лиги Универ"
- Что выбрать мужчине: топ-3 формата (виски-дегустация, коктейли, латте-арт)
- "5 идей подарков мужу/папе/коллеге" — мини-блог внутри лендинга
- Сезонные акценты — блок "На 23 февраля — скидка 15% на корпоративные сертификаты до 21.02"
- Цены и форматы
- Отзывы дарящих "мужу/папе/брату"
- FAQ

#### Корпоративная программа — отдельная подстраница `/events/sertifikat/korporativnym-klientam/`

Это B2B-кусок, обычно дарящие — HR / админ. Здесь:
- Скидки от объёма (10+ / 25+ / 50+)
- Брендинг сертификата (логотип компании на упаковке)
- Закрывающие документы
- Менеджер на постоянной связи
- Доставка одной посылкой в офис

## Дизамбигуэйшн контент (защита бренда от трёх "Лиг")

Трёх "Лиг" — Универ (наш), Барменов России (ligabar.ru), Шоу (ligashow.ru) — путают в выдаче и на агрегаторах. Создаём страницу:

**`/events/ligabarspb-vs-ligashow/`** — "Лига Универ или Лига Шоу: чем отличаемся"
- Сравнительная таблица
- Кто мы: школа барменов с лофтом для ивентов в центре СПб
- Кто Ligashow: выездной кейтеринг при Лиге Барменов России
- Кому что подходит
- FAQ "вы это та же компания, что..."

Это решает 2 задачи:
1. Снимает паразитный трафик "ligashow или ligabarspb"
2. Если пользователь искал ligashow и попал на нас — у него есть быстрый ответ + конверсия не теряется

## Архитектура внутренней перелинковки (после внедрения)

```
[/events/ — hub с фильтрами]
    │
    ├─→ Продуктовые категории (есть): коктейли, вино, кофе, чай
    │       │
    │       └─→ Продуктовые подстраницы (есть + новые: виски, настойки, молекулярка)
    │
    ├─→ ИВЕНТ-ПОСАДОЧНЫЕ (новые): корпоратив, ДР, девичник, мальчишник, свадьба
    │       │
    │       ├─→ ссылаются на 3-5 подходящих продуктов
    │       └─→ ссылаются на /sertifikat/ (как подарочный вариант)
    │
    ├─→ ВЫЕЗДНОЙ ФОРМАТ (есть, переработать)
    │       └─→ ссылается на корпоратив + свадьбу + ДР
    │
    ├─→ СЕРТИФИКАТЫ (новый hub) → подстраницы по получателю + сезону
    │       └─→ ссылается на все продуктовые
    │
    └─→ /blog/ (новый)
            └─→ каждая статья ссылается на 1-2 продуктовых + 1 ивент-посадочную
```

Каждая страница ссылается на 4-7 других — это формирует глубокую внутреннюю экосистему и распределяет PageRank.

## Кому что делегируем

- `content-strategist` — пишет ТЗ для копирайтеров на каждую новую посадочную (в `briefs/`)
- `serp-analyst` — углублённо разбирает выдачу по новым pillar-запросам перед написанием ТЗ
- `schema-engineer` — JSON-LD блоки под каждый шаблон
- `link-strategist` — после создания посадочных — план аутрича на профильные блоги, СМИ, отраслевые каталоги, чтобы качать новые URL
- `analytics-reporter` — настраивает события в Метрике на каждую новую конверсию (заявка / онлайн-покупка сертификата)
